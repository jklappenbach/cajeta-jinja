# cajeta-jinja

A Jinja2-compatible template engine for [cajeta](https://github.com/jklappenbach/cajeta):
lexer, parser, interpreter, the full builtin filter/test/global
library, autoescaping, and loader-backed inheritance — over a
`JsonValue`-shaped context. Extracted from `cajeta-llama`'s chat-template
interpreter and grown to the full dialect.

**Correctness is oracle-driven**: the fixture corpus's expected outputs
are GENERATED by real Jinja2 (pinned version, `tools/gen_fixtures.py`)
and compared byte-for-byte — expectations are never hand-written. The
corpus includes the real chat templates of four model families
(llama3, mistral, qwen25, tinyllama) plus a macro-heavy tool-call
template (qwen3coder), all rendering byte-exact under the
`transformers` whitespace settings.

```cajeta
import dev.cajeta.jinja.Environment;
import dev.cajeta.jinja.Template;
import cajeta.codec.json.Json;

Environment env = heap Environment();
env.trimBlocks(true).lstripBlocks(true);
Template t #= env.compile("Hello {{ user.name | title }}!");
JsonValue ctx #= Json.parse("{\"user\": {\"name\": \"ada\"}}");
String out #= t.render(ctx);        // "Hello Ada!"
```

## Surface

- `Environment` — settings carrier (trim/lstrip, autoescape, strict
  undefined, injected epoch clock for `strftime_now`, template loader);
  compiles `Template`s.
- `Template` — compiled once, renders repeatedly; parse errors carry
  line and column at compile time.
- `JinjaLoader` / `FileSystemLoader` / `MapLoader` — `{% extends %}` /
  `{% include %}` resolve at COMPILE time through the loader; a
  compiled template renders loader-free.
- Statements: `if/elif/else`, `for/else` (tuple unpacking, the full
  `loop.*` incl. `previtem`/`nextitem`/`cycle()`, loop filters),
  `set` (inline + block), `with`, `break`/`continue` (loopcontrols),
  `macro`/`call`/`caller()`, `filter` blocks, `raw`, `block`/`super()`,
  `namespace()`.
- 40 builtin filters, the full test set, `range`/`dict`/`cycler`/
  `joiner`/`lipsum` globals, `raise_exception`, `strftime_now`.
- Anything outside the supported set fails LOUDLY naming construct and
  line — never renders something plausibly wrong.

Documented divergences from CPython-backed Jinja2 (tuple printing,
float repr bounds, deterministic `lipsum`) are listed in the plan's
unit notes.

- Grammar: `grammar/Jinja.g4` is the normative contract; the parser is
  hand-written recursive descent (ANTLR4 has no cajeta target). The
  precedence chain is Jinja2's — verified against its parser, NOT
  Python's (`**` left-assoc, unary minus tighter than `**`, `~`
  between `+` and `*`, chained comparisons, `is` at postfix level).

## Test

    ./run-tests.sh                  # CAJETA=<compiler> to override
    python3 tools/gen_fixtures.py   # regenerate references (review the diff!)

**Toolchain floor**: building or running this library needs a cajeta
release carrying the break/continue drop-chain codegen fix and the
JSON tree-API escape decode (both landed after v0.21.0) — see
`.github/workflows/release.yml` for the pinned version.

Consumers: `cajeta-llama` (chat templates, autoescape off) and later
`cajeta-http` (HTML, autoescape on).
